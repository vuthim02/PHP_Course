# Amazon Clone — Full Project Plan (plain PHP + SQLite)

> **Goal:** a full e-commerce webapp that looks and works like amazon.com on
> **both the client side and the server side**, built from scratch with plain PHP.
> This file is the master plan: stack, technologies, architecture, database,
> features in phases, and step-by-step guides.

| | |
|---|---|
| **Backend** | PHP 8.5 (plain PHP, **no framework**) |
| **Database** | SQLite 3 (single-file, no server, no password) |
| **Frontend** | Vanilla HTML5 + CSS3 + JavaScript (server-rendered by PHP) |
| **Runtime** | PHP built-in server (dev) → Apache / Nginx (production) |
| **Git** | one repository for the whole project |

---

## 1. Vision

We are building a storefront with the **same UX as Amazon**: dark navy header
with a search bar, category menu, product grid, star ratings, a sidebar cart,
a multi-step checkout, order history, and an admin panel. PHP renders every page
on the server (server-side rendering), and a little vanilla JS adds hover menus,
cart count updates, and search autocomplete — no frontend framework.

> **Design note:** we replicate the *layout, colors, and interaction patterns* so it
> *feels* identical. For a personal learning project this is fine. If you ever deploy
> it publicly, remove the "Amazon" wordmark/logo and rename the brand — the Amazon
> name and smile logo are trademarks.

## 2. Stack & Technologies

### 2.1 Backend — PHP 8.5 (plain)
- **Language:** PHP 8.5, NTS build. Runs as a normal CLI/built-in-server process.
- **Database access:** PDO with prepared statements (SQLite driver by default,
  MySQL available by config swap) — the modern, injection-safe way.
- **Sessions:** native `$_SESSION` for login state and the cart.
- **Password hashing:** `password_hash()` / `password_verify()` (bcrypt).
- **Security helpers:** `htmlspecialchars()` for XSS, CSRF tokens on every form,
  `strip_tags()`/`filter_var()` for input, prepared statements for SQL.
- **Config:** a `config.php` file (or `.env`) with credentials — **never committed to git**.

### 2.2 Frontend — vanilla
- **HTML5** semantic layout (header, nav, main, footer) generated by PHP templates.
- **CSS3** — one main stylesheet `amazon.css` replicating Amazon's look:
  dark navy `#131921` header, orange accent `#febd69`, white cards with light-grey
  background, star icons, 4-column responsive product grid.
- **Vanilla JavaScript** (`main.js`, no libraries): mobile hamburger menu, dropdown
  menus, AJAX "Add to Cart" without reloading the page, cart badge counter, and
  simple search autocomplete via a JSON endpoint.
- **No build step.** No Webpack/Vite/npm. CSS and JS are served as plain files.

### 2.3 Database — SQLite 3
- **Why SQLite:** zero setup, no server to start, no password to remember — the
  whole database is one file (`database/amazone.sqlite`). Perfect for learning.
  PHP already has `pdo_sqlite` loaded.
- Relational schema: `users`, `categories`, `products`, `reviews`, `cart_items`,
  `orders`, `order_items` — identical shape to the MySQL plan.
- `db.php` is driver-aware: switch `config.db.driver` to `"mysql"` later and the
  app runs on MySQL too (both use PDO prepared statements).
- Foreign keys enforced via `PRAGMA foreign_keys = ON`.

### 2.4 Tooling
| Tool | Purpose |
|---|---|
| PHP 8.5 built-in server | dev server: `php -S localhost:4000 -t public public/router.php` |
| `php -l` | syntax check |
| PHP PDO (sqlite) | embedded single-file DB — no server, no password |
| `database/setup.php` | CLI script: (re)creates the DB from schema + seed |
| Git | version control |
| (optional) `curl` | test pages / APIs |
| Composer | *optional later* for autoloading; not required for v1 |

## 4. Database Schema

Same relational shape as the original MySQL plan, in SQLite dialect
(`database/schema.sql`, run by `database/setup.php`):

```sql
users        (id INTEGER PK, name, email UNIQUE, password_hash,
              shipping_address, city, zip, created_at)
categories   (id INTEGER PK, name, slug UNIQUE, parent_id NULL, image_url)
products     (id INTEGER PK, category_id FK, name, slug UNIQUE, description,
              price REAL, stock INT, image_url, rating_avg REAL, rating_count INT,
              created_at)
reviews      (id INTEGER PK, product_id FK, user_id FK, rating 1–5 CHECK,
              comment, created_at)             -- UNIQUE(user_id, product_id)
cart_items   (id INTEGER PK, user_id FK NULL, session_token, product_id FK,
              quantity, added_at)             -- cart can work before login
orders       (id INTEGER PK, user_id FK, total REAL,
              status TEXT CHECK IN ('pending','paid','shipped','delivered',
              'cancelled'), shipping_address, city, zip, created_at)
order_items  (id INTEGER PK, order_id FK, product_id FK,
              price_at_purchase REAL, quantity)
```

Key decisions:
- **Money** is stored as `REAL` with two-decimal formatting in `money()`.
  (SQLite has no strict `DECIMAL`; if we ever need exact money math we switch
  to integer cents — or MySQL.)
- **Cart works without login** (guest cart keyed by `session_token`), then is
  merged into the user's cart at login. This mirrors Amazon.
- **Product rating** is denormalized (`rating_avg`, `rating_count`) and recomputed
  after a review is posted.
- **Order items snapshot the price** so later product price changes never affect
  a past order.

## 7. Security Guide (non-negotiable)

1. **SQL injection** — only PDO prepared statements, never string-concatenated SQL.
2. **XSS** — escape every dynamic value with `e()` (= `htmlspecialchars()`, plus
   `ENT_QUOTES`) before output in any view.
3. **Passwords** — `password_hash()` to store, `password_verify()` to check.
   Never store or log plain passwords.
4. **CSRF** — every POST form carries a per-session token; reject mismatches.
5. **Session hardening** — `session_regenerate_id()` on login; short lifetime;
   `session.cookie_httponly = 1`.
6. **File uploads (admin)** — validate extension + MIME, randomize filename, never
   serve PHP from the uploads folder.
7. **Secrets** — DB password lives only in `config.php`, which is in `.gitignore`.
8. **HTTPS** — production only over TLS (dev localhost is fine without).
9. **Never handle real payment data.** The checkout payment step is a mocked form.
10. **Limit DB user permissions** to the app schema only.

```bash
#    http://localhost:4000
```

- **Workflow per feature:** pick a todo from the roadmap → write the SQL → write the
  model → write the controller → write the view → test in the browser → `git commit`.
- **Git discipline:** one small commit per feature; never commit `config.php`
  (add it to `.gitignore`).

## 9. Testing Guide

- **Manual smoke test** after every phase: browse → search → product → add to cart →
  checkout → see order → rate product.
- **`php -l`** every changed file.
- **Edge cases checklist:** empty search, product out of stock, cart quantity = 0,
  login with wrong password, guest cart after login, review when already reviewed,
  admin without login.
- **SQL checks:** re-run `php database/setup.php` and confirm seed counts
  (`products = 12`, `categories = 4` in the setup script output).
- *(Optional later)* PHPUnit for model/unit tests once Composer is added.
